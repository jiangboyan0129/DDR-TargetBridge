# Public release checklist

This candidate changes presentation and engineering, not scientific results. Its local check record is separate from the actual remote release status. The original `v1.0.0` records are preserved in `provenance/releases/v1.0.0/`.

Before merging a candidate: review the diff, ensure no new external scientific data were added, preserve the independent scientific-input lock, run verification and public-core reproduction, render the report/brief/slides, and check the actual GitHub CI result for the exact release commit. Do not regenerate a manifest merely to excuse a changed scientific input.

Author citation identity, truthful personal responsibility and optional software licensing remain decisions for the human owner. Public visibility is not a license. Source investigators retain credit for their experiments; third-party data terms are unchanged.

A local PASS is not a remote CI result. Do not relabel or overwrite the original v1.0.0 tag or assets. Create a new patch release after the new commit has passed CI.
